# Novel Agents

面向长篇中文小说的本地多智能体工作台。远程大模型负责规划、正文和记忆提取，本地小型嵌入模型负责检索；默认按 70 万到 120 万字项目设计，可在轻薄本上运行。

## 必选智能体

1. 总控编排
2. 题材与受众分析
3. 世界观设计
4. 人物设计
5. 总纲设计
6. 人物关系弧线规划
7. 支线与伏笔设计
8. 章节规划
9. 关系场景导演
10. 正文创作调度与共享人味规则
11. 玄幻、校园、都市正文智能体（三选一，按项目正文类型必选）
12. 定稿关系记忆整理与定稿记忆提取
13. 阶段记忆压缩与检索重排

正文之后的审校、润色、读者模拟等智能体仍作为后续可选扩展，不影响当前必选流程。

## 工作流程

```text
项目任务书
  -> 题材分析 + 世界观（并行）
  -> 人物设定
  -> 故事总纲
  -> 人物关系弧线
  -> 支线与伏笔表
  -> 单章规划
  -> 本章关系节拍卡
  -> 正文调度选择玄幻 / 校园 / 都市智能体
  -> 智能体初稿 CHxxx_draft.md
  -> 文风检测 + 人物关系一致性检测（可选）
  -> 作者润色 CHxxx_author.md
  -> 作者确认定稿 CHxxx_final.md
  -> 关系变化提取 + 记忆提取 + 本地向量索引 + 结构化事实库
  -> 下一章规划与写作按需检索
```

只有 `CHxxx_final.md` 会进入记忆。作者稿和智能体初稿不会被当作权威事实。修改定稿后，系统会把该章标记为“过期”，重新索引后才恢复同步；严格模式下，上一章定稿未同步时不能生成下一章。

人物关系也只依据 `CHxxx_final.md` 更新。信任、吸引、依赖和戒备等细微变化可以自动记录；陌生、相识、熟悉、暧昧、相恋等阶段变化默认进入待确认，不会静默改写。作者润色后再定稿时，关系智能体读取的是润色后的最终正文。

## 人物关系系统

- 关系状态按人物组合保存，同时分开记录 A 对 B 与 B 对 A 的信任、吸引、依赖、戒备和主观认知。
- 公开关系、私下关系、称呼、肢体边界、共享秘密、共同经历、未解决矛盾和下一里程碑都会进入章节上下文。
- 章节规划后自动生成关系节拍卡，限制本章可以使用的行为信号和禁止跃迁，允许关系保持、单向靠近、倒退或误判。
- 人物关系一致性审校并入正文质检报告，候选稿仍由一个定点改稿智能体生成，并且必须人工接受后才写入作者稿。
- “人物关系工作台”可以新增、修改、删除和锁定关系，接受或拒绝阶段建议，回退最新关系记录，并重新分析指定定稿章节。
- 修改或删除定稿时，对应关系记录会失效；如果已有后续关系事件，系统会提示人工复核，而不会擅自重写后续状态。

## 记忆何时索引

- 在“章节定稿”中点击“标记定稿并索引”时，自动加入索引队列。
- “扫描定稿变化”只刷新状态，不会擅自把草稿或作者稿写入记忆。
- 修改嵌入模型、向量维度、分块参数或文风学习策略后，界面会提示重建。
- 每达到配置的章节间隔会生成阶段检查点，默认每 10 章一次。
- 写正文时默认暂停本地嵌入，写作结束后继续，减少轻薄本 CPU 和内存争用。

## 长篇记忆结构

- SQLite 保存章节摘要、人物和事件事实、时间线、伏笔、来源哈希、文风观察和检查点。
- NumPy 向量索引保存本地嵌入，当前规模下通常只有数千个记忆块，使用精确余弦检索即可。
- 默认嵌入模型为 `BAAI/bge-small-zh-v1.5`，ONNX、CPU、INT8。
- 默认最大写作上下文为 240,000 个字符。即使远程模型支持 1M 上下文，也只注入当前章节真正需要的事实、原文片段和最近定稿，避免成本和注意力浪费。
- 每个智能体可以单独设置模型参数和记忆权限，包括是否读取事实、原文、伏笔、作者文风，以及最多读取多少个片段。

正文提示词采用分层组合：`正文创作调度与共享规则`保存所有题材共用的去 AI 味要求，三个题材正文智能体只保存各自的附加规则。项目中的“正文类型”决定本章实际调用哪一个智能体；题材智能体的模型参数留空时继承正文调度智能体，再继承全局模型配置。智能体页的“组合预览”可以查看最终提交给模型的完整提示词。

## 轻薄本默认值

```yaml
batch_size: 8
max_parallel_jobs: 1
pause_during_writing: true
checkpoint_every_chapters: 10
target_book_chars: 700000-1200000
```

这些值都可以在“记忆工作台”随时修改。提高并发会增加 CPU、内存和远程 API 压力；同一向量文件的提交仍由系统串行保护，避免并发写坏索引。

## 启动本地工作台

Windows 下可直接双击项目根目录的 `NovelAgents-Control.cmd`，菜单支持启动、关闭、重启、查看状态和打开页面。

也可以使用命令行：

```powershell
python -m novel_agents.web --host 127.0.0.1 --port 8765
```

打开 `http://127.0.0.1:8765`。首次使用真实记忆检索时，在“记忆工作台”点击“准备本地模型”。该操作才会下载模型并导出 INT8 ONNX；测试和普通启动不会自动下载权重。

## Vue 前端开发

前端源码位于 `frontend/`，使用 Vue 3 和 Vite 构建，构建结果会写入 `novel_agents/web_assets/`，由现有 Python 服务继续提供静态页面和 `/api/*` 接口。

```powershell
npm.cmd install
npm.cmd run dev
npm.cmd run build
```

开发时访问 Vite 输出的本地地址；发布或使用 Python 工作台前先运行 `npm.cmd run build`，再按上面的方式启动 Python 服务。

项目页支持编辑项目资料和永久删除项目。修改书名不会改变项目目录 ID；章节数不能降低到已有章节资料以下。删除会同时移除该项目的规划、章节和记忆数据，且正在运行任务的项目不能删除。

智能体页支持修改和删除扩展智能体。必选内置智能体不能删除或修改身份信息，但仍可修改提示词、模型参数和记忆权限。智能体选择列表拥有独立滚动区域，可使用鼠标滚轮或触屏滑动。

模型 API 使用 OpenAI 兼容的 `/chat/completions` 接口。“模型”页面可以维护多条模型配置，分别保存 API 地址、模型 ID、密钥、默认参数和接口能力，并可测试连接、停用、设为默认或删除。默认模型用于没有单独指定模型的智能体；智能体页面可从模型库下拉选择，正文题材智能体仍按“自身配置 → 正文调度智能体 → 默认模型”的顺序继承。

模型配置保存在 `.novel_agents/model.json`。旧版单模型文件会在新服务首次读取时原地迁移为模型库并设为默认模型，不会丢失已有地址或模型参数。接口只向前端返回密钥掩码，不返回明文；默认模型以及仍被智能体引用的模型不能直接删除。服务应保持绑定在 `127.0.0.1`。

### API 密钥只走环境变量

`model.json` 不保存密钥，只保存密钥所在的环境变量名（字段 `api_key_env`）。解析顺序是：

1. 进程环境变量里的专属变量，例如 `NOVEL_API_KEY_DEFAULT`；
2. 工作区 `.env` 文件里的同名变量；
3. 通用兜底变量 `NOVEL_API_KEY` 或 `OPENAI_API_KEY`。

变量名按模型 ID 生成：`default` 模型是 `NOVEL_API_KEY_DEFAULT`，其余是 `NOVEL_API_KEY_MODEL_<ID 大写>`。专属变量优先于通用变量，所以中途接入一个全局 `NOVEL_API_KEY` 不会意外顶掉已经配好的模型。

在“模型”页填写密钥时，密钥会写入工作区 `.env`，注册表里只留下变量名。`model.json` 里如果存在历史明文密钥，会在首次读取时自动迁移进 `.env` 并清空该字段。也可以完全不使用 `.env`，改为在系统或 shell 中导出变量：进程环境变量优先于 `.env`，而调用方显式传入的密钥（“测试连接”场景）优先级最高。

`.env` 已被 `.gitignore` 忽略，不要把它提交进版本库；在 Windows 上 `chmod 0600` 不会真正收紧 ACL，如需限制访问请自行设置文件权限。

## 旧项目兼容

新项目默认启用记忆。旧项目如果没有 `memory/settings.json`，会保持原样，不会自动迁移、建立索引或修改章节。需要使用时可在项目中显式启用。

本次实现不会迁移或索引现有的“龙族”项目。
